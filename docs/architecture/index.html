The phone edge, drawn from its code

A phone becomes the edge of DigitalHome.cloud: a big-tile page (a profile: inventory, check-in/out, a wall switch) that joins a small Python server over USB or by a QR code on the Wi-Fi. The edge checks what the phone sends and passes it, as one JSON contract (dhc-edge/0.1), to Node-RED, an MQTT broker or ROS 2, whose commands come back to the phone's tiles. These seven diagrams show the parts, how a phone joins, what flows, what is kept, two use cases end to end, and the one failure that stopped the whole edge.

Every box cites the lines it comes from, at commit 23b2ca7; the build checked each citation against that commit. The edge serves this pack at /docs/.

Review findings

FindingEvidenceStatus
A backend that stayed connected but stopped reading (its PC asleep, or gone from the Wi-Fi) froze the edge. Events are sent on the phone's thread while deliver() holds the phone's lock, and a write had no time limit: after a few photos the socket was full, the phone's later taps were not read and take_over() waited for the same lock. Measured: 4 events of 8, then nothing; a second phone got no profile in 15 s. Writes now give up after SEND_TIMEOUT_S (10 s) without progress and the link is shut; a test reproduces it. wsserver.py 152–185, 265–277, core.py 69–86 · 07 fixed in 23b2ca7
While a backend is slow (not stuck), each event still waits for it, up to 10 s, on the phone's thread. A queue and a sender thread per backend would take it off the phone's path, at the cost of keeping photos in memory per backend. wsserver.py 250–255, core.py 81–86 · 07 open
A backend joins the list before it gets its status event, so an event emitted in between can reach it first. The adapter's doc says the status comes first. A flow that waits for the status only to read the states is unaffected. Read, not reproduced. wsserver.py 457–467, nodered.py 28–30 open
Events are numbered under the core's lock but handed to the adapters after it, so an event from the phone's thread and one from a backend's (a profile event) can arrive in the other order than their n. Sort by n where the order matters. Read, not reproduced. core.py 69–86, 162–168 open
MQTT and ROS 2 commands carry no token: whoever may publish on the broker or the ROS domain can drive the phone (toast, say, profile). The edge relies on the broker's own users and TLS (--mqtt-user, --mqtt-tls) and on the ROS domain; the Node-RED link has its token, and without one only this PC may connect. mqtt.py 34–38, 75–78, ros2.py 57–60, wsserver.py 359–367 · 01 by design
Photos stay in memory, those of the last 6 events, for the setup page only (/api/photo, this PC only); the events listed there carry each photo's size, not the photo. The record and its photos belong to the backend. core.py 69–80, 251–254, wsserver.py 341–356 · 04 by design
A toggle never turns by itself: it sends the state it asks for and shows it only when a state command comes back, else it falls back after 4 s. Without a backend a switch does nothing, visibly. app.js 74–77, 176–179 · 06 by design
Suspected: a second phone could be credited with a message the first had already sent. It cannot: deliver() passes a frame on only while its link is current, under the lock the takeover holds (atl-phone's fix, kept). wsserver.py 265–277 · 02 checked · no issue
